## Milestones

### Milestone 1: Project Foundation

**Goal:** A running Next.js app deployed to Vercel with basic routing and shared UI components.

**Depends on:** Nothing

**Tasks:**
1. Initialize Next.js project with TypeScript and Tailwind CSS (`npx create-next-app@latest`)
2. Install and configure shadcn/ui for consistent component primitives
3. Set up basic page structure: `/` (home/input), `/results` (coverage results), `/paperwork` (NF form)
4. Configure Vercel deployment (connect repo, set up preview deployments)
5. Add the two reference PDFs to `data/` directory in the repo

**Platform notes:**
- Use Next.js App Router (not Pages Router) — cleaner layout structure
- Tailwind + shadcn/ui gives a professional UI with zero design work for V1

**Verify:**
- `npm run dev` starts without errors
- All three pages render (even if blank)
- Vercel preview URL is live

---

### Milestone 2: Formulary Data Pipeline

**Goal:** The Aetna 2026 formulary PDF is fully parsed into a queryable JSON file that maps drug names to tier, copay, and prior-auth status.

**Depends on:** Milestone 1

**Tasks:**
1. Write a one-time Node.js script (`scripts/parse-formulary.ts`) using `pdf-parse` or `pdfjs-dist` to extract text from `2026_Aetna_Standard_Plan.pdf`
2. Inspect the raw extracted text to understand the PDF's column structure (drug name, tier, coverage notes, prior auth flag)
3. Write a parser that converts the raw text into structured records: `{ drugName, genericName, tier, copay, priorAuthRequired, quantityLimit, notes }`
4. Handle known IVF drug name variations and brand/generic aliases (e.g., Gonal-F = follitropin alfa)
5. Output `data/formulary-aetna-2026.json` and commit to repo
6. Write a type definition file `types/formulary.ts`

**Platform notes:**
- This is an offline build step, not a runtime operation — the JSON file is static and committed
- The hardcoded IVF medication list (Clomiphene, Letrozole, Follistim, Gonal-F, Luveris, Menopur, Lupron, Ganirelix, Cetrotide, Prometrium, Endometrin, HCG, Vivelle patches, Estrace) must all be represented with their brand and generic names as search keys

**Verify:**
- Run `npx ts-node scripts/parse-formulary.ts` successfully
- Output JSON contains all ~20 IVF drugs (or explicitly marks each one as "not found" if absent)
- Each entry has tier, copay, and prior auth fields populated

### Milestone 3: Medication Input UI

**Goal:** A patient can open the app, see a clean list of IVF medications, select the ones they've been prescribed, and submit for lookup.

**Depends on:** Milestone 1

**Tasks:**
1. Build the home page (`/`) with a medication selection component
2. Render the hardcoded IVF drug list as a grouped, checkable list (grouped by drug class: ovulation inducers, gonadotropins, GnRH agents, progesterone support, trigger shots, estrogen support)
3. Add a "free text" fallback input field for drugs not in the list
4. Add "Check Coverage" submit button that navigates to `/results` with selected drugs as query params or URL state
5. Add minimal header with app name and a one-line description of what the app does

**Platform notes:**
- Use shadcn/ui `Checkbox` and `Card` components
- Drug groups: Ovulation Induction (Clomid, Letrozole), Gonadotropins (Follistim, Gonal-F, Menopur, Luveris), GnRH Agents (Lupron, Ganirelix, Cetrotide), Progesterone (Prometrium, Endometrin, injections), Trigger Shots (HCG/Ovidrel), Estrogen (Vivelle, Estrace)

**Verify:**
- All IVF drugs appear, grouped correctly
- Checking multiple drugs and clicking submit passes them to the results page
- Free text field accepts additional drug names

### Milestone 4: Coverage Results

**Goal:** For each selected medication, the patient sees whether it's covered, what tier it's on, estimated copay, and whether prior authorization is required.

**Depends on:** Milestones 2 and 3

**Tasks:**
1. Build `/results` page that reads selected drugs from state/params
2. Load `formulary-aetna-2026.json` and match each selected drug (fuzzy match on brand and generic names)
3. Render a results card per drug:
   - Drug name + generic equivalent
   - Covered / Not Covered badge
   - If covered: Tier (1/2/3/4), estimated copay, quantity limit
   - If covered with prior auth: orange "Prior Authorization Required" banner
   - If not covered: red "Non-Formulary" badge with "Generate Paperwork" CTA
4. Add a summary bar at top: "X of Y drugs covered"
5. Add a "What to ask your doctor" section below results (static tips: request generic, ask for specialty pharmacy, mention prior auth needed)

**Platform notes:**
- Fuzzy matching: use `fuse.js` for tolerant drug name search
- No API calls at runtime — pure client-side JSON lookup

**Verify:**
- Selecting covered drugs shows correct tier and copay from the Aetna JSON
- Selecting a non-covered drug shows "Non-Formulary" badge
- Prior-auth drugs show the orange banner
- "Generate Paperwork" button appears for NF drugs

### Milestone 5: Specialty Pharmacy Finder

**Goal:** After seeing coverage results, a patient can find specialty fertility pharmacies near them via a Google Maps deep-link.

**Depends on:** Milestone 4

**Tasks:**
1. Add a zip code input field to the results page (or home page)
2. On the results page, add a "Find Specialty Pharmacies Near You" section
3. Generate a Google Maps search URL: `https://www.google.com/maps/search/specialty+pharmacy+fertility+medications/@{lat},{lng}` — using the zip code as the location hint
4. For V1, use a static deep-link with the zip appended as a query: `https://www.google.com/maps/search/specialty+pharmacy+fertility+{zip}`
5. Add helper text: "Look for pharmacies that specialize in fertility medications — not all pharmacies stock injectable gonadotropins."
6. List 3-4 known national specialty pharmacy chains as static text (e.g., Axia Women's Health Pharmacy, CVS Specialty, Walgreens Specialty, Freedom Fertility Pharmacy)

**Platform notes:**
- No Google Maps API key needed for V1 — plain search URL opens in browser tab
- V2 will replace this with the Photon Health API or Google Places API

**Verify:**
- Zip code entry generates the correct Maps URL
- Clicking the link opens Google Maps in a new tab with the search pre-filled
- Static pharmacy list is visible without requiring Maps interaction

### Milestone 6: Non-Formulary Prior Auth Paperwork

**Goal:** For any non-covered drug, the patient can generate a pre-filled Aetna prior authorization PDF ready to send to their provider.

**Depends on:** Milestone 4

**Tasks:**
1. Install `pdf-lib` for runtime PDF manipulation
2. Store `precertification-request-for-prescription-drugs.pdf` as a static asset in `public/templates/`
3. Inspect the PDF's form fields (if it is a fillable PDF form) or identify the text positions to overlay
4. Build `/paperwork` page: collect minimal patient details (name, date of birth, member ID — no server storage, client-only)
5. Pre-fill the PDF with: patient info from input fields, drug names from the NF results, today's date, and a placeholder for the prescribing provider's info
6. Provide a "Download PDF" button that downloads the filled document
7. Add instructional text: "Print or email this form to your prescribing doctor. Ask them to complete the clinical justification section and submit to Aetna."

**Platform notes:**
- If the Aetna PDF is a flat (non-fillable) PDF, use `pdf-lib` to overlay text at fixed coordinates — map out coordinates manually
- If it's a fillable form (AcroForm), use `pdf-lib`'s form field API — easier
- All processing is client-side; no patient data is sent to any server

**Verify:**
- Download a filled PDF with sample patient data
- Drug name(s) appear in the correct form section
- Date is pre-filled with today's date
- Form is legible and printable

**Platform notes:**
- The message is dynamically generated from the actual coverage results
- "Open MyChart" is a static link in V1; V2 would use Epic's SMART on FHIR API
- Use the browser Clipboard API for the copy button

**Verify:**
- Message correctly lists covered and non-covered drugs from the results

## Data Model (V1 — No Persistence)

All data in V1 is stateless — nothing is stored on a server. The only persistent artifact is the committed JSON file.

| Entity | Storage | Milestone | Notes |
|---|---|---|---|
| Formulary data | `data/formulary-aetna-2026.json` (static, in repo) | 2 | Pre-processed from PDF; admin updates by re-running the parse script |
| Selected medications | React state / URL params (session only) | 3 | Lost on page refresh — acceptable for V1 |
| Patient details for paperwork | Client-side form state only | 6 | Never sent to server |
| Message template | Generated client-side, never stored | 7 | Copy to clipboard only |
